Webby / Homeserver integration history

From a Caddy listing to a shared card system

This timeline captures the project history, including the messy parts from the conversation: style ownership, Caddy coupling, layout regressions, preview generation, hostname assumptions, and the Webby changes that fell out of each trap.

Timeline

Jun 8
rewrite foundation

Webby became a Rust CLI with bags and providers

The project moved away from an experiment into an installable CLI with built-in local, tailnet, funnel, public, and internal bag concepts. The important architectural choice: Webby manages app staging and provider activation; it should not need every host to use the same serving mechanism.

What worked Bag selection, provider deploy tests, and public/internal mirror behavior gave Webby a stable core.
What was hidden The internal Caddy path was already special. That coupling later turned into browse mode.
Jun 10
trap launcher UI

The first visual index used live iframe previews

The generated Webby index was redesigned as a compact launcher. The first implementation used lazy iframe backgrounds so each tile could show the actual app. It looked more useful than text entries, but it loaded every hosted app inside the index page.

Trap Visual fidelity was bought with runtime cost. The launcher became responsible for executing the apps it linked to.
Lesson Preview generation belongs outside the runtime page. Cards should show static assets, not live embedded apps.
Jun 11
performance screenshots

Hover jank and screenshot capture forced a second pass

Firefox profiling showed input stalls and too many CSS transitions. Webby removed large-surface hover animations, added containment, and moved from iframes to static screenshots.

Trap
  • Chrome headless and CDP screenshot paths could hang or capture blank pages.
  • Even CSS-only previews had hover jank when transitions touched large surfaces.
Resulting Webby changes
  • webby preview for static JPEG previews.
  • Reduced hover work to compositor-friendly transforms.
  • Later switched preview capture to uvx shot-scraper.
Jun 18
packaging reliability

Release packaging and shot-scraper made Webby more operational

Webby gained release machinery, crate metadata, and a non-interactive Cloudflare Wrangler fallback. The preview backend moved to uvx shot-scraper, because the earlier Chrome path was not reliable enough on real documentation sites.

Trap Headless browser behavior is not a stable API. A page can be simple and still hang one capture route.
Change Use a proven capture tool and keep screenshot generation as an explicit command.
Jun 19
source of truth shared renderer

The homepage and Webby generated pages were solving the same card problem twice

The conversation started by comparing how home.ankitson.com was generated with what Webby produced. The homepage had its own curated JSON and card CSS. Webby had its own generated listing. Tools, files, and app cards drifted between text entries, icons, and screenshots.

Trap Two renderers meant two layout systems, two style systems, and two places to fix card behavior.
Decision Use a frontend primitive, not a Rust HTML helper: a Web Component with bundled JS and CSS.
Jun 19
component data contract

<webby-card-grid> became the reusable renderer

Webby now emits normalized card data and a reusable component. The component owns the card markup, preview treatment, grouping, dark styling, and responsive behavior. Pages pass data; they do not rebuild the card DOM.

Input Card items with id, title, href, description, category, tmp, and previewUrl.
Output A grouped card grid rendered in Shadow DOM, styled by bundled defaults and optional CSS custom properties.
Jun 19
layout regressions stable sizing

The homepage card grid looked right, then broke in several different ways

The original homepage layout had one property worth preserving: rows used the full browser width. During the migration, card max-width experiments made the cards too tiny, created gaps in sparse rows, and eventually made top rows lose columns because max width was treated like fixed width.

Failures seen
  • Cards became too small after adding caps.
  • The Datasette/Resume row developed a large gap.
  • Top rows fell from four cards to two.
  • Auto-fit caused cards to grow, then snap smaller when a new column appeared.
Resulting Webby change
  • Add stable-card-width.
  • Use a target width for dense rows.
  • Let sparse rows expand up to a max.
  • Expose --webby-card-stable-width and --webby-card-max-width.
Jun 19
homepage one surface

The separate tools page was folded into the Caddy homepage

The Webby internal bag moved to noIndex: true. Instead of serving a separate tools page, the homepage fetches /webby/webby-cards.json, rewrites relative URLs under /webby/, and renders Webby cards alongside curated static services and app-runner cards.

Important live decision The explicit tools.home.ankitson.com handler was removed from the live Caddyfile, but the Caddyfile was intentionally not committed.
Committed homeserver shape The tracked homepage files now include index.html, services.json, and an original.html comparison page.
Jun 19
generated assets previews

Preview generation had to stay boring

The homepage needed preview images for curated services and app-runner apps. The constraint was explicit: do not create another script if a uvx shot-scraper loop in the Justfile is enough.

Result just homepage-previews reads services.json plus the app-runner manifest and writes JPEGs under .webby-previews/.
Later gotcha When the Job Search URL changed, its preview had to be regenerated too: job-search.jpg.
Jun 19
hostname assumption manifest URL override

Job Search exposed the app-runner manifest assumption

The Job Search app was really running inside the shared app-runner container on port 9006, routed by Caddy at jobs.dev.ankitson.com. But the homepage card came from an app-runner manifest that derived every URL as <subdomain>.home.ankitson.com.

Discovery path ps and ss inside app-runner showed /apps/job-search/app serving bun src/server.ts on 9006.
Fix App-runner dashboard entries gained optional dashboard.url; Job Search now points at https://jobs.dev.ankitson.com.
Jun 19
Caddy coupling mode removal

Browse mode and indexMode were identified as the wrong abstractions

Once the homepage consumed manifests, Webby's browse mode was just a Caddy directory-listing adapter living inside a general-purpose tool. It hardcoded one host's behavior into Webby's public mode system.

Removed
  • IndexMode::Browse
  • webby gen-browse
  • templates/browse.html
  • The Justfile browse regeneration recipe
  • The two-value indexMode config
Final cleanup The final shape is simpler: Webby always writes card assets, writes index.html by default, and skips the root page only with noIndex or --no-index.
Jun 19
publishing hygiene copy hardening

Public staging revealed metadata-copy risk

While getting the public Kickoff app back, a Webby publish path had copied local metadata and cache directories into a public bag. The local bag was cleaned, but public edge caches can make stale assets look alive for a while.

Trap Static deploy tools will faithfully publish whatever the bag contains, including files that should never have been staged.
Webby change Directory staging now skips .git, .wrangler, .DS_Store, node_modules, and logs.
Commit split
landed history hygiene

The final commits separated framework work from app content

The Webby repository got separate commits for the shared card/manifest renderer and the public Kickoff app. The homeserver repository got a homepage integration commit, but the live Caddyfile change stayed uncommitted by request.

Webby commits
  • feat(cards): add reusable card manifest renderer
  • feat(public): add kickoff world cup app
Homeserver commit feat(homepage): render webby cards on homeserver, dated from the staged file mtimes.

What changed in Webby because of this

Cards became data first

Webby now emits webby-cards.json. A host page can consume the bag without scraping directories or reimplementing app discovery.

Rendering moved to a component

webby-card-grid.js owns DOM and CSS. Rust produces data; frontend pages compose the renderer where they need it.

Modes got simpler

Webby writes a standalone index by default. noIndex means another page owns the root experience. browse and indexMode are gone.

Layout behavior became explicit

The stable card-width mode exists because plain responsive grid behavior was not enough for the homepage's full-row visual requirement.

Previews are generated assets

Preview screenshots are produced with shot-scraper and served as static JPEGs, avoiding iframe cost and headless Chrome edge cases.

Host-specific behavior moved out

The Caddy directory-listing adapter was removed. Host integrations now happen by consuming card manifests, not by adding host-specific modes to Webby.
